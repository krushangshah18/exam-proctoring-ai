    Alembic Migration Workflow (for RDS)                                                    
                                                                                          
  When you add a new model/column                                                         
                                                                                          
  1. Edit models.py — add the column/table as usual.                                      
   
  2. Generate the migration (from server/ directory):                                     
  cd /home/krushang/Desktop/exam-proctoring-ai/server       
  source .venv/bin/activate                                                               
  alembic revision --autogenerate -m "describe_what_changed"
  This reads your models.py, diffs against current DB schema, and creates a new file in
  alembic/versions/.                                                                      
                                                                                          
  3. Review the generated file before applying — autogenerate isn't always perfect:       
  - Adding NOT NULL columns to tables with existing rows → add                            
  server_default=sa.text('...') to the op.add_column call                                 
  - Check that the down_revision points to the correct previous migration                 
  - Verify downgrade() is correct                                                         
                                                            
  4. Apply to RDS:                                                                        
  alembic upgrade head
  It reads DATABASE_URL from .env automatically and runs against your RDS instance.       
                                                                                          
  5. Verify:                                                                              
  alembic current        # shows which revision RDS is at                                 
  alembic history        # shows full chain

  Important rules for this project                          
                                                                                          
  - Always add server_default when adding NOT NULL columns to existing tables — you have
  existing rows in prod (as you saw with the a408ac074e9f migration)                      
  - Run from server/ directory — that's where alembic.ini lives
  - .env must be loaded — alembic/env.py reads DATABASE_URL from environment. Since it's  
  in server/.env, either python-dotenv loads it automatically or you can export it first: 
  export $(grep -v '^#' .env | xargs) && alembic upgrade head                             
  - Never edit an already-applied migration — create a new one instead
